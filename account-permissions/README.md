# 账号与权限配置页面

入口为管理系统侧栏「系统管理 → 账号与权限」，独立地址 `/operation-workbench/account-permissions/`。

当前交付是可交互的配置草稿页面，不是登录或鉴权服务。新增、编辑、停用、删除只操作当前浏览器的 `xiong-access-drafts-v1` 本地存储；导出 JSON 标注 `enforcement: not_connected`。不生成真实账号、密码或会话，不隐藏现有业务数据，不限制页面、下载、接口或 AI 问答。草稿不能用作敏感人员信息的管理系统。

支持五种角色模板及自定义权限；门店来自现有直营、加盟看板目标目录，按直营 / 加盟分组，不推断区域。新增门店不会自动授权。模板只提供初始功能权限，门店需显式选择；普通角色不默认授予推广修改或审批权限。门店标识目前仅用于草稿，接入后端时须映射到正式门店主键。财务模板配置现有报表的查看和导出，不代表已有独立财务页面。

验证：`node --test tests/test_account_permissions.mjs`，并使用浏览器检查新增、编辑、校验、持久化、筛选和移动端布局。

生产部署：代码验证并推送 GitHub main 后，在 Mac mini 的干净 main 副本运行 `zsh scripts/deploy_account_permissions.zsh`。该脚本确认 Mac mini 硬件、工作区干净、HEAD 等于 GitHub main；仅部署权限页面静态文件和主导航 HTML，逐文件核对云端 SHA-256，不改运营数据或定时任务。正式链接接受 200，或既有登录保护的 302 跳转；须再用已登录浏览器检查页面。正常总看板发布也会携带这个目录。

后续生效需要：可信统一登录、服务端管理员鉴权、账号及门店授权持久化、所有业务接口和下载的门店过滤、汇总重算、AI 工具数据权限校验、操作授权及审计。不能只靠前端菜单隐藏实现数据隔离。
