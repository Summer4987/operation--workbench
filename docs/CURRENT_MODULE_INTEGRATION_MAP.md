# 现有模块嵌入图

这份清单用于把当前项目里的已有能力嵌入 AI 业务中心，并标出还缺什么。

## 总览

| 中心 | 当前成熟度 | 已有模块 | 下一步 |
| --- | --- | --- | --- |
| 运营中心 | 中 | 上午运营采集、经营日报、实时单量、余额巡检、云端看板 | 先接健康监控和 AI 日报 |
| 推广中心 | 中 | 饿了么点金、预算预览、预算执行、美团预算页 | 先做建议和审批，不直接全自动 |
| 货流中心 | 中 | 库存看板、云端门店下单、出库单生成 | 补销量联动和订货建议 |
| 财务中心 | 低 | 可复用经营日报和推广数据 | 新建账单解析和利润表 |
| 加盟业务中心 | 低 | 文档处理、销售单据工具 | 新建合同、资料和流程中心 |

## 运营中心

### 已有模块

- `morning-ops/run_morning_ops.py`
  - 上午运营一键采集总入口。
  - 适合接入任务注册表。
- `business-report-dashboard/chrome_cdp_reports.py`
  - 经营日报和评价下载浏览器自动化。
  - 需要接入登录/验证码阻塞识别。
- `business-report-dashboard/process_reports.py`
  - 经营日报处理。
  - 需要接入数据产物校验。
- `scripts/realtime_order_income.py`
  - 实时单量收入采集。
  - 需要接入心跳和数据更新时间校验。
- `store-inspection/run_all_balances.py`
  - 余额巡检入口。
  - 需要接入余额不足提醒。
- `scripts/build_workbench_data.py`
  - 看板数据生成。
  - 适合作为运营中心数据汇总节点。
- `scripts/deploy_workbench_to_cloud.zsh`
  - 云端发布。
  - 需要接入发布后校验。

### 缺口

- 统一任务状态。
- 每日健康报告。
- AI 日报。
- 异常解释和建议。
- 人工接管后继续。

### 建议接入顺序

1. 任务注册表。
2. 运行状态文件。
3. 真实产物校验。
4. 状态页。
5. AI 日报。

## 推广中心

### 已有模块

- `dianjin-prototype/`
  - 饿了么点金规则和演练界面。
- `scripts/build_ele_dianjin_rules.mjs`
  - 构建点金规则。
- `scripts/build_promo_budget_preview.mjs`
  - 推广预算预览。
- `scripts/run_current_budget.zsh`
  - 当前时段预算执行。
- `scripts/run_evening_budget.zsh`
  - 晚间预算执行。
- `store-inspection/budget-editor.html`
  - 预算编辑界面。
- `store-inspection/meituan-budget.html`
  - 美团预算页面。
- `store-inspection/meituan_budget_cdp.py`
  - 美团预算浏览器自动化。

### 缺口

- ROI 计算。
- 出价调整逻辑。
- 审批队列。
- 预算动作的执行后校验。
- 高风险动作的保护规则。

### 建议接入顺序

1. 预算和出价只做建议。
2. 建立待确认动作列表。
3. 你确认后执行。
4. 执行后自动校验页面结果。
5. 再逐步放开低风险自动执行。

## 货流中心

### 已有模块

- `inventory-board/`
  - 库存看板和云端库存服务。
- `inventory-board/app/main.py`
  - 后端服务入口。
- `inventory-board/app/order_generator.py`
  - 出库单生成。
- `inventory-board/scripts/sync_order_outputs.py`
  - 云端出库单同步到本地。
- `order-preview/`
  - 订单预览和异常页面。

### 缺口

- 和门店销量数据打通。
- 自动预测明天/本周需求。
- 缺货预警。
- 滞销预警。
- 保质期和损耗字段。
- 订货建议和审批。

### 建议接入顺序

1. 先把库存状态接入总控制台。
2. 接入门店销量。
3. 做缺货/滞销预警。
4. 生成订货建议。
5. 最后做确认后自动订货。

## 财务中心

### 已有模块

- 可复用数据：
  - 经营日报收入。
  - 推广预算和推广费。
  - 库存出入库。
  - 门店订单数据。

### 缺口

- 平台账单下载。
- 账单解析规则。
- 费用分类。
- 门店利润表。
- 推广投入产出。
- 异常扣费提醒。

### 建议接入顺序

1. 先做账单文件归档规范。
2. 做账单解析器。
3. 做门店利润表。
4. 做费用异常提醒。
5. 做月度财务报告。

## 统一待补模块

这些能力不是某一个中心独有，而是整个 AI 业务中心都需要。

| 模块 | 作用 | 优先级 |
| --- | --- | --- |
| 任务注册表 | 定义所有任务、入口、时间、产物 | 高 |
| 任务状态文件 | 记录每次任务进度和结果 | 高 |
| 健康监控器 | 判断任务是否真实完成 | 高 |
| 通知系统 | 失败和异常主动提醒 | 高 |
| AI 日报 | 每日总结和建议 | 中 |
| 审批队列 | 高风险动作先确认 | 中 |
| 操作日志 | 预算、出价、订货、财务动作留痕 | 中 |
| 数据字典 | 统一门店、平台、字段口径 | 中 |
| 权限配置 | 区分自动执行和人工确认 | 中 |

## 第一批最该补齐的文件

建议下一步新增这些“底座文件”，先让系统有骨架：

- `config/tasks.example.json`
  - 所有自动化任务的注册表模板。
- `scripts/task_status.py`
  - 写入和读取任务状态。
- `scripts/check_operation_health.py`
  - 健康监控器。
- `docs/OPERATION_CENTER_MVP.md`
  - 运营中心 MVP 详细方案。

这些文件先旁路接入，不替换现有脚本。
