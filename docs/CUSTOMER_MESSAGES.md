# 直营门店消息复盘

生产入口：运营看板 → 直营店运营数据中心 → 直营门店消息复盘。

- 5 家直营店 × 美团/淘宝闪购。美团 4 个独立账号，保利中心按总部会话所属门店匹配。
- Mac mini 的 `morning-ops/run_morning_ops.py` 在评价页采集后运行 `scripts/collect_customer_messages.py`；正式 launchd 仍为每天 08:00，无须新增定时任务。
- 默认目标为中国时区前一日，重查最近 3 个完整日期；当天仍在继续的旧会话也读取。失败范围重新读取一次。任何账号失败不阻断其余门店，最终非零退出触发既有早间异常记录。
- 淘宝必须在原生选择器按店铺 ID 切店，核对店名及聊天 iframe 的 shopId；等待聊天组件就绪、滚动页面并展开浮动入口，再验证顾客消息标签、单聊/三方均未筛选、只看未读关闭。逐屏去重虚拟会话列表，核对总高度对应会话数。
- 美团关闭已知介绍/提示框，不点击发送、退款、开票、确认操作。全部顾客消息逐页到末尾，包含没有 DOM id 的三方群聊。群聊按实际发送方/门店信息区分归属。
- 普通消息、AI/自动回复、系统事件、订单/售后/发票卡片均保留。图片、音视频下载为本机附件；无法下载或解析的记录标为待复查，不静默丢弃。平台只展示日期时不补造时分秒，语音原件不冒充转写结果。
- 页面展示逐店逐平台的核验状态，失败/不完整不会显示成“无消息”。核验仅覆盖平台当前可见记录，无法恢复已删除或不可访问的历史。淘宝/旧版三方群聊没有总消息数时，核验依据明确标为滚动起点重复复查，不宣称平台服务端总数已对账。
- 看板的“已回复”与“业务已解决”分开。聊天中同意/承诺退款、开票或补发不等于动作成功。

## 数据和发布

原始 JSON、逐次采集和附件保存在被 Git 忽略的 `outputs/customer_messages/YYYY-MM-DD/`，不包含 Cookie、令牌、请求头或签名附件地址。`latest.json` 为当次目标日期检查结果。

`render_customer_messages.py` 生成 `business-report-dashboard/direct-dashboard/customer-messages/` 的首页和逐日归档，并复制本机已保存附件。现有 Mac mini 云端发布脚本在部署时重新生成并发布到原有登录保护的看板路径；不创建公开分享。

## 只读恢复

在 Mac mini 生产 checkout 执行（Python 使用生产 `.venv`）：

```sh
python scripts/collect_customer_messages.py
python scripts/collect_customer_messages.py --date 2026-10-14 --store 朝阳门店 --platform 淘宝闪购
```

仅补采子范围时保留同一天其它已采集范围。恢复平台登录/验证后只重跑失败项；不要为了修复客服采集重新执行推广预算。打开会话可能更新平台已读状态，采集不发送顾客消息，不处理业务动作。

开发验证：`python -m unittest discover -s scripts -p 'test_customer_messages*.py'`，并执行早间采集状态、登录隔离相关回归测试。
