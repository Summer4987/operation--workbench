# 晨间故障隔离与续跑

2026-11-02 的生产故障暴露了总部页面超时中止整条任务、分店范围遗留影响总部采集，以及跨日旧页面挡住刷新入口的问题。

- 登录态预检使用自己的临时标签页；导航异常重试一次，真实登录/验证码仍阻断对应正式操作。
- 晨间总预检失败只记录异常，不再阻断正常平台、直营独立账号、日报和余额等独立任务。双平台预算各自在提交前重新检查登录态。
- 总部评分、评价和客服采集在读取前，通过可见界面恢复“全部门店”并确认范围；恢复失败不采集，也不把失败当作无消息。
- 运行检查点放在生产本机 `outputs/morning_recovery/`。`--resume` 只复用当天、同预算时段、同预览/正式模式的已成功步骤；评价及客服额外只重试失败账号或门店平台范围。预算复用原始运行起点汇总，避免成功步骤被新一轮的空结果覆盖。
- 正式定时入口遇到普通失败时每5分钟续跑一次，严格保留现有08:00–10:50启动窗口。窗口外不自动补做预算；验证码需要人工处理，系统不代答。
- 终态生成后再发布一次轻量数据，避免正式看板一直停留在任务结束前的运行中状态。

龙虾店长的跨日恢复在独立应用仓库实现：旧页面仅用于核对原门店身份，完成真实重载、当天数据稳定校验后才交给原有授权和调价流程；门店变化、未确认编辑和验证页均继续阻断。

部署：推送GitHub main后，Mac mini保留运行产物并执行fast-forward拉取；运行 `scripts/install_macmini_operation_launchd.zsh --scripts-only` 更新现有正式入口，保持定时计划不变。只在Mac mini执行只读生产复查。
